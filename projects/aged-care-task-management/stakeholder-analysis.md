# Stakeholder Analysis & RACI

## Aged Care Daily & Weekly Task Management

**Project Type:** Business Process Improvement
**Role:** Business Analyst

---

## 1. Purpose

This stakeholder analysis identifies the people who are directly or indirectly affected by the proposed improvement to the task-management process.

The analysis helps determine:

* Who uses the process
* Who is affected by the change
* Who provides requirements
* Who makes decisions
* Who needs to be consulted
* Who needs to be kept informed

---

# 3. Stakeholder Needs

## Care Staff

Care staff need:

* Clear task instructions
* Clear task ownership
* Easy access to assigned tasks
* Simple completion recording
* A way to report exceptions
* Minimal additional administrative work

### Main Concern

The new process should make work easier rather than create unnecessary documentation.

---

## Registered Nurse (RN)

RNs need:

* Visibility of relevant outstanding tasks
* Visibility of overdue tasks
* Awareness of task exceptions
* Ability to follow up when required

### Main Concern

Important tasks or exceptions should not be hidden within informal communication.

---

## Clinical Care Coordinator (CCC)

CCCs need:

* Visibility of recurring tasks
* Visibility of outstanding and overdue tasks
* Consistent task-management processes
* Ability to monitor task activity

### Main Concern

The process should provide a reliable overview without requiring excessive manual follow-up.

---

## Facility / Care Management

Management needs:

* Improved operational visibility
* Consistent processes
* Appropriate accountability
* Reduced unnecessary administrative effort
* Better identification of process issues

### Main Concern

The improvement should provide measurable business value.

---

## IT / Application Support

IT or application support would need:

* Clear functional requirements
* Defined user access
* Technical requirements
* Support and maintenance expectations
* Appropriate security controls

### Main Concern

The proposed solution should be practical to implement and support.

# 5. RACI Matrix

RACI stands for:

* **R — Responsible:** Performs the activity.
* **A — Accountable:** Ultimately responsible for the outcome.
* **C — Consulted:** Provides input.
* **I — Informed:** Kept up to date.

The following RACI is a simplified example for this portfolio case study.

| Activity                     | Care Staff | RN  | CCC | Management | IT | BA |
| ---------------------------- | ---------- | --- | --- | ---------- | -- | -- |
| Identify task requirements   | C          | C   | A   | C          | I  | R  |
| Define task ownership        | C          | A   | R   | C          | I  | C  |
| Create recurring tasks       | I          | C   | A/R | C          | C  | C  |
| Complete assigned task       | R          | I   | I   | I          | I  | I  |
| Record task exception        | R          | C   | C   | I          | I  | I  |
| Review exception             | C          | A/R | R   | I          | I  | C  |
| Monitor outstanding tasks    | I          | R   | A   | I          | I  | C  |
| Define business requirements | C          | C   | C   | A          | C  | R  |
| Define solution requirements | C          | C   | C   | C          | C  | R  |
| Support UAT                  | R          | R   | R   | A          | C  | R  |
| Approve business outcome     | I          | C   | C   | A          | I  | C  |

# 6. Stakeholder Engagement Approach

The proposed engagement approach would include:

### Care Staff

Use short discussions, interviews or workshops to understand:

* Current task communication
* Common pain points
* Exceptions
* Usability concerns

### Registered Nurses

Discuss:

* Monitoring requirements
* Follow-up needs
* Escalation requirements
* Visibility requirements

### Clinical Care Coordinators

Discuss:

* Recurring tasks
* Coordination requirements
* Reporting needs
* Operational visibility

### Management

Discuss:

* Business objectives
* Expected benefits
* Priorities
* Implementation constraints

### IT / Application Support

Discuss:

* Technical feasibility
* Integration requirements
* Access and security
* Support requirements

# 7. Key Stakeholder Risks

| Risk                                    | Potential Impact                    | Mitigation                                    |
| --------------------------------------- | ----------------------------------- | --------------------------------------------- |
| Staff perceive the system as extra work | Low adoption                        | Involve staff during requirements and testing |
| Requirements differ between roles       | Conflicting expectations            | Conduct stakeholder workshops                 |
| Task ownership is unclear               | Outstanding tasks remain unresolved | Define ownership rules                        |
| Too many notifications                  | Notification fatigue                | Agree notification rules                      |
| Solution is difficult to use            | Low adoption                        | Conduct usability testing                     |
| Technical limitations                   | Delayed implementation              | Engage IT early                               |

---

# 8. Business Analyst Observation

The stakeholder analysis highlights that the solution should not be designed around technology alone.

Different users have different priorities:

**Care Staff → Easy task management**

**RN → Clinical visibility and follow-up**

**CCC → Coordination and oversight**

**Management → Operational improvement**

**IT → Feasibility and supportability**

Understanding these differences is important when gathering and prioritising requirements.

---

# 9. Assumptions

This stakeholder analysis is based on a simulated portfolio project.

In a real project, stakeholder roles, decision-making authority and RACI assignments would be validated with the organisation before being finalised.
